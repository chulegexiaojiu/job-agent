# 本地求职助手 · job-agent

Windows 本地岗位核验、公司研究与真实素材简历工具。实验性预览版；MIT 许可证。

当前版本提供 Windows 本地工作台：API 配置、加密凭据、真实素材库、浏览器详情与有界列表采集、岗位截图与文字交叉核验、带来源复核的公司研究、分项评分、岗位定制 Word 草稿与招呼语，以及独立的沟通／网申计划和执行账本。

**默认不发送。** 开聊、回复后发送附件和单页网申已有实验性 UIA 适配器；真实执行须显式启用本机站点策略并启动执行。合成页面已完成本地浏览器测试，BOSS 真实详情只读预检已通过，但尚未验证真实站点发送、送达或网申提交，不能视为已可无人值守投递。

## 架构一览

```text
用户输入（岗位链接 / 简历素材 / 指令）
        │
        ▼
┌───────────────────┐
│    Agent 规划层    │  任务拆解 · 步骤排序 · 状态机流转
└─────────┬─────────┘
          │ 工具调用
          ▼
┌────────────────────────────────────────────┐
│                  工 具 层                   │
│  🌐 浏览器采集     📄 文档解析    🔍 联网研究 │
│  (UIA 读取页面)    (DOCX/PDF)   (web_search)│
└─────────┬──────────────────────────────────┘
          │ 证据（网页文字 + 截图 + 来源引文）
          ▼
┌───────────────────┐
│     结果核验层     │  截图×文字交叉核验 · 引文逐字复核 · 分项评分
└─────────┬─────────┘
          ▼
  可追溯产出（简历草稿 / 公司研究 / 执行账本）
          │
          └── 默认不发送：真实投递须显式授权本机策略
```

每一步都落盘留证：采集清单带 SHA-256 校验，研究结论须由引文逐字支持，草稿附来源清单，投递结果计入账本。

## 使用工作台

首次使用：安装 Python 3.10+（包含 Tcl/Tk，并加入 PATH），下载或克隆项目，双击 `check-api.cmd` 配置自己的模型接口。API 四项检测通过并保存 Key 后，双击 `start.cmd`，无须重复配置。接口还需支持研究步骤的 Responses `web_search`；四项检测不包含联网研究能力。

1. 在“真实素材库”导入 DOCX、带文字层 PDF、TXT 或 Markdown。已有素材在本机导入，不会自动上传原文件。姓名、电话、邮箱单独保存在本地，模型只接收已确认的去标识素材。扫描 PDF 暂不自动 OCR，解析不完整会报错。
2. 选择确实发生且可以解释的条目，点击“所选条目属实”。支持 Ctrl / Shift 多选和 Ctrl+A。确认包含项目标题里的机构、身份和日期；来源文件中的主张不自动视为已核实事实。撤销已用素材的确认后，旧草稿会标记过期，需重新生成。
3. 在 Edge / Chrome 当前标签页打开一个 BOSS 岗位详情页，滚动至顶部，然后在工作台点击“导入当前浏览器岗位页”。程序会读取该页的岗位文字和公司信息，裁剪岗位区域截图，加入队列并自动开始不发送分析。截图时浏览器可能切到前台，请保持页面不变。也可在浏览器打开 BOSS 搜索结果，在工作台点击“自动采集当前列表”：每轮选择 1～5 个（默认 3），浏览上限选择 1～20 屏（默认 1）。程序从可见结果中跳过已有链接，必要时滚动或点击唯一可识别的“下一页”，收集足够候选后依次打开详情页、截图并导入，完成后自动开始分析。末尾、无进展、搜索条件变化或访问限制会停止。请只保留一个显示 BOSS 的浏览器窗口，其余最小化。此功能不自动输入搜索词；浏览器停在最后一个采集岗位，下一轮需自行返回列表或更换搜索结果。
4. 也可手动粘贴岗位链接及网页文字，选择岗位截图，或先用系统截图工具截取岗位区域，再点击“粘贴剪贴板截图”，随后“加入待办”并“分析待办岗位”。不要包含头像、聊天或联系方式。应包含公司、职位、城市、人数、职责及要求。单个岗位有问题时暂停该项并继续后续；鉴权、权限或限流错误会停止整个批次，避免持续失败请求。
5. 双击岗位查看核验结果、公司资料、来源链接、评分和处理记录。草稿完成后可打开本地文件夹。采集和分析不会自动开始投递；沟通与网申从单独的标签页操作。

浏览器导入使用 Windows 辅助功能读取当前详情页，不读取 Cookie 或登录凭据，不执行页面脚本或调用招聘网站隐藏接口，不触发“立即沟通”或上传。截图保留岗位标题、公司卡片和可见岗位描述的原始像素裁剪，不保存完整浏览器窗口。Chrome / Edge 若返回黑屏，则使用经过前台及遮挡检查的指定可见区域截图；黑屏、多个候选窗口、页面变化或布局无法识别都会停止。显示验证码、登录页或访问限制时不会尝试处理。页面截图中的公司名或岗位名被截断、识别错字时仍会暂停，不以近似匹配放行。单页导入超时上限 35 秒，批次上限为 20 秒加每个岗位 45 秒、每屏 5 秒。点击“停止采集 / 分析”可停止后续采集，关闭工作台也会终止采集子进程。批次遇登录、验证、访问限制、标签切换或异常跳转立即停止；单项布局或截图失败会记录原因并继续其他岗位。停止或超时前已完成的证据会保留，已导入岗位留在待办，不自动发起分析。可使用原有手动导入备用。少量页面采集成功不代表平台允许大规模自动操作。

自动采集的 `capture.json` 保存规范化岗位链接、时间、截图范围、文字及截图 SHA-256；导入前验证哈希，再将清单复制至对应岗位目录的 `source-capture.json`。批次 `batch.json` 逐项落盘记录成功、跳过及失败。重复链接不重复创建任务或请求模型。此来源校验只证明文件与采集记录一致，不代替截图识别与公司事实核验。

已暂停岗位可在补齐素材后点击“继续所选岗位”重新分析。若原始截图截断或文字有误，先选中该岗位，在上方填写同一完整岗位链接、新的完整文字和截图，再点“用上方内容更新所选来源”。旧来源、图片和草稿归档于该岗位的 `source-revisions/`；旧研究、分数、可用草稿和未执行计划立即失效，之后需重新核验并建立计划。更新本身不调用模型、不发送；已成功／结果未知的记录及额度保留。分析或投递执行期间拒绝更新。同一标准化链接仍不会因普通重复导入而被覆盖或创建第二个任务。

工作流：网页文字提取 → 独立图片提取 → 关键信息交叉核验 → 20～500 人、AI 实习/校招筛选 → 独立联网研究 → 读取公开网页并逐字核验引用 → 独立复核结论是否由引文支持 → 岗位质量与个人匹配评分 → 选择并排序已确认素材 → Word 草稿及来源清单。

岗位质量权重为技能成长 40%、业务前景 30%、公司背景 20%、未来跳槽认可度 10%；个人匹配另计。公司规模无法确认、截图冲突、公司身份不明、所有来源无法读取或素材未确认，都不会生成可用简历结论。研究使用现有接口的 Responses `web_search`，需要服务商实际支持；来源站点无法访问时会保留失败状态，不把搜索摘要当作核实结果。身份复核使用已读取的网页，并对返回的主体关联引文再次逐字核对；普通结论及其日期仍须由各自引文支持。岗位截图核验的是招聘页面披露的人数，不代表独立审计的员工数量；其他来源的人数口径或日期不明时保留为未确定事项。模型复核是辅助检查，不等同于人工事实核查。

简历草稿保留被选素材原文，不自动创造新业绩或改写项目身份；保留已确认教育背景。姓名和联系方式仅在本地回填。草稿文件夹包括 `resume-draft.docx`、`greeting-draft.txt`、`manifest.json`。清单记录岗位、素材位置、文档校验值和未发送状态。到岗时间遵循实际投递日加 14 天；草稿写相对安排，清单中的当天推算只作参考。每周 5～7 天、实习 6 个月及以上；这些已确认安排同时提供给匹配评分。重新分析会清空旧分数并将旧草稿标为过期，重新通过后才显示新的可用草稿。

计数栏从投递账本读取今日新岗位触达预占、今日附件预占，以及累计开聊、简历发送、网申成功和结果待核实数量。计划和预检不计成功。草稿清单里的 `sent: false` 表示生成时未发送；此后投递结果以账本及对应回执为准。

## 沟通与网申（实验性）

1. 在岗位页选择有有效草稿的岗位，切到“沟通与网申”，生成开聊计划。计划会再次检查公司研究、截图核验、岗位资格、已确认素材、招呼语模板和草稿文件哈希。
2. 打开一个与计划完整 URL 相同的浏览器标签页，执行“只读预检所选计划”。预检不切换页面、不填写、不上传、不发送；因此通常逐页预检。有效预检不保证稍后页面仍相同，执行时会重新检查。
3. 回复后发送：在岗位页选中一个岗位，在链接框填入对应会话完整 URL，点击“读取招聘方回复”。只有最新回复明确索取简历、会话含对应公司／职位卡片时才建立简历计划。普通招呼、拒绝、面试安排、条件性请求和敏感要求不自动发送。回复证据及截图需完整，消息本身及采集时间均须在过去 7 天内。当前适配器要求消息内可唯一识别的 `message-time`／`message-timestamp` 辅助功能元素提供带时区的 ISO 日期时间；缺时间、仅相对时间、时间不明确、未来或过期回复均只保留采集记录，不建立自动发送依据。重新读取旧消息不会刷新消息有效期；发送前再次核对同一文字和消息时间。没有常驻自动轮询或任意内容自动回复。
4. 网申：填入岗位原文或最新招聘方回复中的完整 HTTPS 链接，生成网申计划，再导入该站点的单页表单配置。配置还必须引用这个岗位已读取的公司研究页面，页面须含原文身份引文和确切网申 URL。导入配置不会启用真实执行。配置格式见 `examples/form-profile.example.json`。
5. 真实执行由本机 `private/delivery-policy.json` 和显式执行共同控制。缺少配置时使用默认不发送策略。GUI 的执行按钮只在本机 live 策略有适配器白名单时启用，点击后会给隔离 worker 传 `--live`；CLI 不传此参数始终只读预检。启用前应核实平台适用规则、站点页面及本机授权范围。程序不会自行启用。

默认策略（可参考 `examples/delivery-policy.example.json`）：

```json
{
  "mode": "dry_run",
  "daily_new_jobs": 120,
  "daily_resume_sends": 120,
  "enabled_adapters": []
}
```

`mode` 可选 `dry_run`／`live`；适配器 ID 为 `boss-uia-v1` 或 `form:<配置id>`。两个限额都只能为 1～120。配置中的 live 和白名单只是本地执行开关，不证明平台许可或适配器已完成生产验证。

live 批次要求先打开首个目标页面；后续使用同一个已绑定窗口切换到计划中的精确 URL，每次重新核验。页面发生非计划跳转、标签切换、登录／验证／限流／额度提示时停止整批。任意外链、验证码和风控均不尝试绕过。同一本地工作区的采集、只读预检、回复读取与投递 CLI worker 共用进程锁，进程退出后释放。不同工作区、其他程序及手动浏览器操作不受此锁控制；操作期间请勿切换标签或操作浏览器。

### 限额、去重和异常恢复

- 开聊和直接网申共享每日 120 个新岗位触达上限；同一岗位不能通过多个渠道重复新触达。已成功开聊后，最新招聘方明确提供的网申链接可作为后续动作，不再次计入新岗位数；聊天结果不明则不自动跟进。
- 聊天附件与网申附件合计每日最多 120 次预占；达到上限后停止新开聊和后续投递批次。同一岗位已有附件成功或结果不明时，不跨渠道再投一次。开聊次数不等于已投简历份数。
- 执行前原子预占额度；成功、执行中和结果不明都占用额度。结果不明可能发生在尚未发送时，保守保留额度，不能视为成功。按本机日期统计，到岗日期按实际执行日加 14 天。
- `planned` 待预检、`previewed` 预检通过但未发送、`blocked` 已暂停、`reserved` 已预占、`executing` 执行中、`succeeded` 已保存成功凭据、`unknown` 结果待核实且禁止自动重试。暂停后修正原因可以重新预检；成功和未知计划不会自动重试。
- “停止执行”或关闭工作台会通知 worker 取消，给出 12 秒合作退出期，随后必要时 terminate／kill，各最多再等待 5 秒并回收。已发生的发送无法撤回；已预占而没有完整成功证据的记录会变成 `unknown`。没有自动把未知结果改为失败或释放额度的功能。
- 附件文件名含岗位 ID 与内容哈希，发送前核对本地文件及素材绑定。页面上传预览核对文件名；生产页面不提供远端哈希时，不能证明招聘系统最终存储的文件内容。

### 当前支持边界

BOSS 开聊适配器只接受精确目标和唯一控件；若点击后平台已自动问候或出现已有消息，会暂停为结果待核实，避免再发一遍。附件发送需可直接识别的文件选择入口、专属附件预览和送达状态。实际页面不符合这些条件时暂停；不会猜控件、用默认简历或承诺真实站点可用。

网申仅支持已审核配置的单页表单：姓名、邮箱、电话、到岗日期、每周天数和实习月数。数值字段使用已确认范围内的每周 5 天／6 个月。未知问题、复选框／声明／同意项、下拉或单选、多页流程、签署、付款、证件和验证码均不自动作答。回执必须在同页出现带唯一编号的指定文本；跳转或无回执进入待核实。

本地执行记录保存在 `private/workspace.sqlite3`、`private/delivery-runs/`、`private/outbound/` 和 `private/replies/`，可能包含简历、联系方式、聊天截图和网申链接中的敏感参数；不要提交或公开这些文件。

### 批量岗位输入

“批量导入 JSON”接受最多 1000 条一批的 UTF-8 JSON 清单；没有总筛选数量限制。截图路径可相对清单文件目录。重复链接会跳过，失败记录会计数。

```json
[
  {
    "url": "https://jobs.example.com/positions/123",
    "text": "粘贴实际网页中的公司、岗位、城市、人数和完整 JD",
    "screenshot": "screenshots/job-123.png"
  }
]
```

所有岗位输入、来源网页、研究、截图、简历及操作记录仅保存在 `private/`。研究公司时不携带申请人素材；仅评估岗位匹配时把已确认素材发送给配置的云端模型。配置窗口的合成数据说明仅适用于 API 检测，工作台分析会发送你导入的岗位文字和截图。

## 配置与检测

1. 双击 `check-api.cmd`。
2. 确认窗口显示的是你使用的接口地址及模型。程序尝试识别本机已有配置；无法唯一识别时须填写高级配置。仓库不提供服务商地址、账号或 Key。
3. 粘贴该服务商的 API Key，按回车。

窗口会依次检测文本生成、随机图片识别、JSON 结构化输出、工具调用格式，并自动显示结果。图片只包含合成岗位和随机校验值，不读取简历、桌面或招聘账号。工具调用仅检查返回格式，不执行模型返回的操作。最多发送 5 次请求；不自动重试，鉴权失败或限流后停止。

默认在文本样本通过后，用 Windows 当前用户的 DPAPI 加密保存 Key。其他检测失败仍会显示实际失败结果。可以取消保存，也可以用“清除已存 Key”删除凭据。再次打开时，直接按回车可使用已存 Key 复测。更换接口地址后不会复用旧地址的 Key。

- 本地配置：`private/connection.json`
- 加密凭据：`private/credential.dpapi`
- 检测报告：`private/api-capabilities.json`

`private/` 已加入 `.gitignore`。不要手动强制提交该目录。未使用任何真实 Key 的本地测试不能证明远程 API 支持相应能力；一轮真实样本通过也不等于生产可靠性已验证。

“停止后续检测”会取消尚未发送的请求。已经发出的请求会等待响应或超时，可能仍产生接口费用。关闭窗口不会触发投递。

## 环境

Windows 11、Python 3.10+（含 Tcl/Tk）。`check-api.cmd` 在缺少 Pillow 时安装图片组件；`start.cmd` 在缺少工作台依赖时安装 `requirements.txt`。可先运行 `python -m pip install -r requirements.txt` 手动安装依赖。每台机器需自行配置服务商地址、模型及 Key；仓库不包含个人接口配置或密钥。

UI 使用 Tkinter；SQLite 记录本地状态；Pillow 读取截图；python-docx 输出 Word；pypdf 提取 PDF 文字；Windows 下使用 pywinauto 读取浏览器辅助功能树。当前不包含正式 PDF 简历渲染导出、自动输入搜索词、常驻回复轮询或通用多页网申。

高级配置可调整协议、模型、输出长度和超时。自动协议会优先尝试 Chat Completions；未成功且符合切换条件时尝试 Responses。只检测成功选中的协议；不会宣称两种协议都已通过。不同服务商的 Key 不能仅凭字符格式可靠判断来源，请核对窗口中的地址。

## 开发检查

```powershell
python -m compileall -q job_agent tools tests
python -W error::ResourceWarning -m unittest discover -s tests -v
```

测试使用虚构凭据、模拟返回、隔离子进程和本机 HTTP 服务，不调用外部模型。覆盖协议解析、鉴权限流、加密凭据、来源与引文、素材及草稿失效、截图和有界翻页、入库去重、账本额度和并发互斥、回复证据、附件绑定、未知结果禁止重试，以及工作台停止／关闭／超时后的实际子进程回收。

另外可显式运行真实浏览器的本地合成页面测试（会将 Edge 切到前台）：

```powershell
python -m tools.check_chat_ui
python -m tools.check_delivery_ui
```

两者只使用回环 HTTP 服务和合成申请人／附件，不联系招聘方、不调用模型、不使用生产账本。聊天测试复用生产身份检查和 UIA 交互，仅允许本地测试 URL；覆盖开聊、读取带明确时间的回复、附件选择／本地发送、重复附件拒绝及绑定窗口导航。工作台到真实 CLI、回复登记与建计划另由隔离子进程测试覆盖，其中 UIA 采集被合成实现替换；尚未把真实 UIA 采集与工作台后续链路作为同一个端到端测试。网申测试覆盖填写、文件选择、浏览器计算的 SHA-256、一次本地 POST 和编号回执。服务器只接收合成字段、文件名及哈希，并不测试真实招聘系统的文档存储。结果在 `private/selfcheck/chat-ui/`、`private/selfcheck/delivery-ui/`；成功不能替代真实平台端到端验证。

`tools/check_workflow.py` 是开发用的显式联网自检，会产生 API 调用费用，只使用合成申请人和公开公司资料。它不代表存在真实招聘，也不做投递；报告保存在 `private/selfcheck/`。该脚本自行生成合成岗位截图；可显式运行 `python -m tools.check_workflow`，它不是普通用户启动入口。

独立命令行检测器保留在 `tools/check_api.py`；不传密钥命令行参数，交互终端会隐藏输入。

GitHub Actions 配置提供 Windows / Python 3.10、3.12 离线回归和暂存文件检查，不运行付费模型或真实浏览器外发。提交前运行 `python -m tools.check_release`；它读取 Git 暂存区，检查公开路径白名单及常见敏感值，不能替代人工隐私审查。开发和数据边界见 [CONTRIBUTING.md](CONTRIBUTING.md)、[SECURITY.md](SECURITY.md)。
